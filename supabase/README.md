# Supabase — настройка

## 1. Ключи

Уже прописаны в `src/config.js`:

- `SUPABASE_URL` — адрес проекта
- `SUPABASE_ANON` — публичный anon-ключ

Anon-ключ **безопасно** держать в репозитории: он по замыслу открыт в любом
клиентском приложении, а доступ к данным закрывает Row Level Security
(миграция `0002_rls.sql`). Ключ `service_role` в репозиторий класть нельзя
никогда — он обходит RLS полностью.

## 2. Схема

Открыть **SQL Editor → New query**, вставить целиком `supabase/schema.sql`,
нажать **Run**. Файл идемпотентный — повторный запуск ничего не сломает.

Если удобнее по частям, миграции лежат отдельно и запускаются по порядку:

| # | Файл | Что делает |
|---|------|-----------|
| 1 | `migrations/0001_schema.sql` | Таблицы, типы, индексы, триггеры, функции |
| 2 | `migrations/0002_rls.sql` | Политики Row Level Security |
| 3 | `migrations/0003_seed.sql` | Каталог снаряжения |
| 4 | `migrations/0004_sleep.sql` | Трекер сна и цели подъёма |

## 3. Подтверждение почты

**Authentication → Providers → Email**

- включить **Email**
- включить **Confirm email**

Именно этот переключатель включает в приложении экран «Почта не подтверждена».
Без него любой введённый адрес будет пускать внутрь сразу.

**Authentication → URL Configuration**

- **Site URL**: адрес GitHub Pages, например `https://<логин>.github.io/<репозиторий>/`
- **Redirect URLs**: добавить туда же и `http://localhost:4173/` для локальной разработки

## 4. Схема данных

```
profiles ─┬─< workout_logs   тренировки: вес/удержание/угол, массив мышц, флаг рекорда
          ├─< sleep_logs     ночи: отбой, подъём, длительность, качество
          ├─< unlocked_gear >── gear_catalog   снаряжение и множители опыта
          ├─< achievements   разблокированные достижения
          └─< boss_defeats   пройденные челленджи
```

Особенности:

- `handle_new_user()` создаёт профиль автоматически при регистрации.
- `sync_level()` выводит уровень из опыта и хранит лучшую серию.
- `fill_sleep_duration()` считает длительность сна на сервере и корректно
  обрабатывает переход через полночь: 23:40 → 05:10 это +330 минут.
- `sleep_logs` уникальна по паре (пользователь, дата пробуждения) — одна ночь
  не может задвоиться. Дата — это **день пробуждения**.
- `weekly_compliance(weeks)` возвращает выполнение недельной нормы.
- `sleep_summary(days)` — подъёмы с отклонением от цели.

## 5. Проверка, что RLS работает

```sql
-- под обычным пользователем вернёт только свои строки
select count(*) from workout_logs;
select count(*) from sleep_logs;

-- вернёт 0 строк, а не ошибку
select * from profiles where id <> auth.uid();
```
